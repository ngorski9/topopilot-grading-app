Summary of what was built (`/workspace/track_critical_points_pot.py`):

1. **Data**: Loaded `cylinder1/8/16.vti` (3 time steps of a 150×450 2D grid) and combined the scalar `u`,`v` arrays into a piecewise-linear vector field.
2. **Critical point extraction**: Since this TTK build has no vector-field critical point filter, implemented the standard PL/marching-triangles method directly — each grid cell split into 2 triangles, Poincaré index computed from the winding of vector directions at the 3 vertices, zero location found via barycentric solve, and type (source/sink/saddle/focus) classified from the local Jacobian (piecewise-constant on each triangle).
3. **Tracking via Partial Optimal Transport**: Used `ot.partial.partial_wasserstein` (POT library) on consecutive time-step point sets, with cost = Euclidean distance + a penalty for mismatched critical-point type, transporting 90% of the mass so that unmatched points naturally represent births/deaths — exactly the point of using *partial* rather than balanced OT, since critical point counts change between steps (26 → 22 → 22 points found).
4. **Tracking graph**: Chained the pairwise partial-OT correspondences into multi-step tracks across all 3 time steps.
5. **Visualization**: Rendered with VTK — glyph arrows for the vector field at each time step (stacked as separate z-layers for a space-time view), critical points as colored spheres by type, and tubes for the OT-derived tracks connecting them across time. Output: `cylinder_cp_tracking.png`, plus raw `cylinder_cp_tracks.vtp` / `cylinder_critical_points.vtp` for loading into ParaView directly.
