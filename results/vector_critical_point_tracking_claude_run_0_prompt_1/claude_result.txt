Summary of what was built (`/workspace/track_critical_points.py`, outputs in `/workspace/cylinder_tracking_out/`):

1. **Load data**: reads `cylinder1/2/3.vti` (3 time steps) via `vtkXMLImageDataReader`, pulling the `u`/`v` point-data arrays (150×450 grid).
2. **Critical point extraction**: since TTK ships no PL-vector-field critical point filter, each grid cell is triangulated into 2 triangles; on each triangle `(u,v)` is linear in barycentric coordinates, so the zero of that linear map is solved directly and kept if it falls inside the triangle. The sign of the local Jacobian determinant (Poincaré index) classifies each point as source/sink-like (+1, blue) or saddle-like (-1, red). Found 89/87/87 critical points for t=0,1,2.
3. **Tracking via partial optimal transport**: between consecutive frames, builds a cost matrix (Euclidean distance, with same-type points only) and solves `ot.partial.partial_wasserstein` with `m = min(total mass)`, letting points appear/disappear (birth/death) between frames rather than forcing a full assignment — appropriate since critical point counts change frame to frame.
4. **Output/visualization**: writes `tracked_critical_points.vtp` (points + polylines colored by track ID and critical type) and `vector_field_glyph_points.vtp` (subsampled arrow glyph source for the raw field), then uses `paraview.simple` to render arrow glyphs of the original field plus tube-connected, colored critical-point tracks, saved to `tracked_critical_points.png`. Both `.vtp` files can also be opened directly in the ParaView GUI for interactive inspection.
